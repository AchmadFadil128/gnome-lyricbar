# LyricBar v0.1.13

Lyrics matching fix for non-Latin track metadata.

## Fixed

- Synced lyrics now load for tracks whose artist or title uses non-Latin scripts (Chinese, Japanese, Korean, Cyrillic, and others). The fallback search that runs when LRCLIB has no exact match previously rejected every candidate for these scripts, so the panel showed only the track title ([#8](https://github.com/fikrilal/gnome-lyricbar/issues/8)).
- Matching keeps script-specific details intact, including voiced kana (`ガ` vs `カ`), while Latin diacritic folding (for example `Motörhead` = `Motorhead`) is unchanged.

## Changed

- Compact styling for the optional settings button in the top bar.
- Refreshed development dependencies and CI workflow actions; no runtime impact.

## Verification

- `npm run verify` and `npm audit` clean on the release commit.
- Runtime evidence against live LRCLIB: the `周杰伦 — 晴天` scenario with a decorated album name (for example `晴天 - Single`) now resolves the fallback search and returns the synced lyric timeline.
- CI green on `main` (36 test files).

## Notes

- Tracks that are missing from LRCLIB (for example `李荣浩 — 鸿门宴`) still fall back to the track title until an entry exists upstream.
- Cached "no lyrics" results expire within 6 hours after upgrading, so an affected track may briefly still show the title after the update.
